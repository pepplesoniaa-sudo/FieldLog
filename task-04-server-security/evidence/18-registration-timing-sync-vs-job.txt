2. ARCHITECTURAL & RESILIENCE ANALYSIS:
--------------------------------------------------------------------------------
Why synchronous email in registration requests is an architectural anti-pattern:
1. Third-Party Latency Spikes: When external mail servers (e.g. Gmail/SendGrid) experience network congestion or rate-limiting delays, registration response times balloon to 5+ seconds, leading users to believe the app is frozen and click submit repeatedly.
2. Catastrophic Coupling: If the external mail provider suffers an outage, an in-request implementation crashes the entire registration pipeline with HTTP 500 errors, preventing new users from onboarding even though our primary database is 100% healthy.
3. Resource Exhaustion: Long-running HTTP requests tie up Node.js server connections and memory while waiting for idle TCP socket I/O.
4. Correct Behavior: Offloading to pg-boss enqueues an immutable job in 1.86ms and immediately returns HTTP 201 Created to the browser. The persistent background worker handles SMTP retries, exponential backoff, and dead-letter queue routing without degrading user experience.
